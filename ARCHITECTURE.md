# Архитектурная концепция и технический план

Этот документ описывает архитектуру и план реализации для симуляционной игры, основанной на концепции из `Concept.md`.

### Архитектурная концепция

Приложение будет построено на основе клиент-серверной архитектуры:

1.  **Frontend (Клиентская часть):**
    *   **Технологии:** HTML, CSS, JavaScript (без фреймворков для простоты и скорости).
    *   **Тип:** Одностраничное веб-приложение (SPA).
    *   **Ответственность:** Рендеринг всех интерактивных UI-компонентов, отправка действий пользователя на сервер и отображение полученного от сервера состояния игры.
    *   **Компоненты:**
        *   Окно чата для взаимодействия с ИИ-ролями.
        *   Интерактивная Jira-доска (канбан) с drag-and-drop.
        *   Панель с динамическими метриками (бюджет, риски, KPI).
        *   График Ганта для визуализации таймлайна проекта.

2.  **Backend (Серверная часть):**
    *   **Технологии:** Python с использованием легковесного фреймворка Flask.
    *   **Ответственность:**
        *   **Simulation Engine (Ядро симуляции):** Управление всей логикой игры, состоянием проекта (GameState), ходом времени (спринтами) и расчетом влияния решений игрока на метрики.
        *   **API:** Предоставление RESTful API для связи фронтенда с бэкендом (например, эндпоинты `/state`, `/chat`, `/move_task`, `/end_sprint`).
        *   **LLM Module (Модуль ИИ-ролей):** Модуль будет эмулировать команду. На данном этапе будет реализован как **"мок-модуль" (симуляция)**, который возвращает предопределенные, но контекстно-зависимые ответы, имитируя поведение реальной LLM. Это позволит построить и протестировать весь игровой цикл без зависимости от внешних сервисов.

### Технический план реализации

Работа будет разбита на следующие этапы:

1.  **Настройка проекта и бэкенда:**
    *   Создать новую структуру проекта с папками `frontend` и `backend`.
    *   Настроить базовый сервер на Flask в `backend/app.py`.
    *   Определить основные API-маршруты (`/get_state`, `/send_chat_message`, `/end_sprint`).

2.  **Разработка ядра симуляции:**
    *   В `backend` реализовать классы для управления состоянием игры (`GameState`) и логикой (`SimulationEngine`).
    *   Движок будет отвечать за инициализацию проекта по сценарию "Биллинговая система" и обновление метрик в конце каждого спринта.

3.  **Создание симуляции ИИ-ролей:**
    *   В `backend` написать "мок-модуль" (`MockLLM`), который будет генерировать ответы для ролей (разработчик, менеджер, стейкхолдер) в зависимости от контекста диалога и состояния проекта.

4.  **Интеграция фронтенда и бэкенда:**
    *   Переместить существующие файлы (`index.html`, `style.css`, `script.js`) в папку `frontend`.
    *   Переработать `frontend/script.js` для работы с бэкендом: все данные о состоянии игры будут запрашиваться с сервера через `fetch` API, а действия пользователя — отправляться на сервер.

5.  **Реализация UI-компонентов на фронтенде:**
    *   **Jira-доска:** Добавить в `index.html` и `style.css` элементы для канбан-доски. Реализовать на JavaScript логику перетаскивания карточек (задач), которая будет отправлять изменения на сервер.
    *   **График Ганта:** Интегрировать легковесную JavaScript-библиотеку (например, Frappe Charts или Google Charts) для отрисовки графика Ганта на основе данных о задачах, полученных с сервера.

6.  **Тестирование и проверка:**
    *   После завершения разработки запустить сервер.
    *   Написать Playwright-скрипт для комплексной проверки. Скрипт будет эмулировать действия игрока: отправит сообщение в чат, передвинет задачу на доске, завершит спринт и сделает скриншот для визуального подтверждения, что все компоненты системы (метрики, чат, доски) обновились корректно.
